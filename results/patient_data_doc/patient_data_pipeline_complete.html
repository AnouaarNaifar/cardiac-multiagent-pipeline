01What's
different

A modality with no preprocessing step

ECG has a five-stage signal pipeline before a single feature exists. MRI has slice selection, cropping, encoding and mask arithmetic. This modality has none of that — and the absence is the design, not a gap.

One row of the UCI Cleveland file already carries thirteen clinical fields in their clinical units. There is nothing to denoise, no lead to pick, no volume to segment. compute_feature_dict translates UCI's numeric category codes into readable labels and passes the continuous values through untouched. That is the whole "preprocessing".

Two other things set this modality apart, and both matter for how it is judged:

  • The ground truth is balanced. heart_disease_present has a prevalence of 0.459. On ECG, the target diagnoses are rare, so precision is swamped by false positives and a precision of 0.38 can still be the best flag in the module. Here, precision above roughly 0.46 is genuine signal rather than the base rate — a much more demanding bar, and a much more readable one.
  • Every flag predicts the same outcome. ECG flags each target a different scp_code set; MRI flags each target a different pathology group. Here all seven are competing predictors of one binary target, which is why the validation table reads like a scoreboard.
02The
data

UCI Heart Disease, Cleveland subset

303 patients, 13 input features and a target, from UCI repository id 45 (doi.org/10.24432/C52P4X). Fetched once via ucimlrepo — for the authoritative column names, types and descriptions — then saved locally to uci_heart_disease/processed_cleveland.csv and variables_metadata.csv.

The agent reads that local file and never makes a live network call at runtime. This matches the project's local-first pattern for every reference dataset (PTB-XL, ACDC) and removes a runtime dependency on UCI's servers: ucimlrepo does not cache, confirmed empirically — two consecutive fetches each took the same ~1.7 s.

Why binarise the target

Every published benchmark on this dataset uses num > 0, and — more to the point — the raw 5-level severity scale is not what any of these flags claim to predict. A flag that says "elevated resting blood pressure" is a candidate predictor of disease presence, not of its severity grade. Binarising is the honest match between the claim and the measurement.

03Feature
dict

Thirteen keys, and the line they draw

compute_feature_dict(row) is the single source of truth for evidence_ref: the LLM may only cite keys that exist here. Its internal rule is a clean split between two kinds of field.

Nine fields are reported exactly as they arrive; four are numbers the agent will later interpret only through a deterministic threshold, never through a guess in the summary.
HandlingKeysRule
Direct read age_years · sex · chest_pain_type · fasting_blood_sugar_elevated · resting_ecg_result · exercise_induced_angina · st_segment_slope · n_major_vessels_colored · thalassemia_result Category code → label lookup, or a straight pass-through. No interpretation.
Qualitatively
interpreted		 resting_bp_mmHg · cholesterol_mgdl · max_heart_rate_achieved_bpm · st_depression_oldpeak_mm Value passed through untouched. Whether 260 mg/dl counts as "high" is decided only in detect_flags_patient, by a validated threshold.

Missing values are reported, never guessed

Only ca (4 patients) and thal (2 patients) are ever missing — UCI encodes them ? in the raw format, NaN once loaded. They become None, and build_patient_clinical_summary omits them from the text entirely rather than printing "None". Every threshold in detect_flags_patient guards for None per field, so the related flag is simply skipped. This is the same "None where not computable" convention the ECG and MRI agents already use.

Keys are deliberately not namespaced

No patient. prefix. Confirmed directly in code that neither ecg_agent.py nor mri_agent.py actually namespaces its keys — an earlier docstring note suggesting future agents should was never implemented. It would be redundant anyway: every citation downstream is the pair (agent_id, feature), never a bare feature name, so a cross-modality clash cannot occur.

04The seven
flags

Deterministic decision logic

Seven flags, computed by pure threshold logic with no LLM anywhere. Three of them have no threshold at all — they pass through an already-binary or categorical field.

if resting_bp_mmHg            >  140.0        → "high_resting_bp_suspected"
if cholesterol_mgdl           >  240.0        → "high_cholesterol_suspected"

predicted_max = 208.0 - 0.7 * age_years       # Tanaka
if max_heart_rate_achieved_bpm < 0.91 * predicted_max
                                              → "reduced_exercise_capacity_suspected"

if st_depression_oldpeak_mm   >= 0.8          → "significant_st_depression_suspected"
if exercise_induced_angina    is True         → "exercise_induced_angina_present"
if n_major_vessels_colored    >= 1            → "multiple_vessels_involved_suspected"
if thalassemia_result         != "normal"     → "abnormal_thallium_result_suspected"

PatientDecisionPlan.skip_llm_call is always False here, and reason always None. Unlike ECG (fewer than two QRS complexes) or MRI (no computable ejection fraction), this dataset has no field whose absence makes a record unanalysable — only ca and thal are ever missing, and every other field is always present. The fields are kept purely for structural consistency with the other two agents' decision plans.

05Calib-
ration

Testing the textbook cutoffs instead of inheriting them

140 mmHg and 240 mg/dl are universally recognised clinical thresholds. They were still swept — because a cutoff that is optimal for making a diagnosis is not necessarily optimal for firing a human-review alert.

src/patient_data_flag_validation.py caches each patient's feature dict once, then tries many candidate thresholds cheaply against heart_disease_present. It never edits the agent: a finding is applied by hand afterwards in patient_data_agent.py, the same discipline that moved ECG's tachycardia threshold from 100 to 120 bpm.

Why 0.91 and not 0.90

Because the flag fires below the predicted maximum, a higher percentage fires on more patients. So 0.91 does not trade recall for F1 — it wins both, 0.705 against 0.683 recall and 0.669 against 0.664 F1, giving up only a point of precision. 0.92 buys a little more recall still (0.712) but F1 drops to 0.651, so the plateau ends there.

Resting blood pressure and cholesterol were swept across 110–170 mmHg and 180–300 mg/dl. In both, F1 only improves by flagging almost everybody, and precision never meaningfully clears the 0.459 base rate while doing so:

The decision, stated plainly

Resting blood pressure and cholesterol are simply weak predictors of coronary disease in this dataset, at any threshold. So the clinically meaningful cutoff was kept and the weakness reported honestly, rather than chasing a statistically marginal and clinically meaningless gain by flagging nearly every patient. The same pattern is already documented for ECG's irregular_rhythm_suspected, which was likewise kept at CV 0.15.

Recall-favouring throughout. These flags feed a human-review alert, not a final classification, so a missed true case is treated as a worse failure than an extra false positive that a reviewer dismisses — the same philosophy applied to ECG's tachycardia threshold.

06The
agent

From feature dict to contribution

src/patient_data_agent.py — 459 lines. One entry point, generate_patient_contribution(row, …), producing structured findings and never a diagnosis: that remains the Sep Agent's job.

The summary

- Age: 63 years
- Sex: male
- Chest pain type: typical_angina
- Resting blood pressure: 145 mmHg
- Serum cholesterol: 233 mg/dl
- Fasting blood sugar > 120 mg/dl: yes
- Resting ECG result: probable_lvh
- Maximum heart rate achieved (exercise test): 150 bpm
- Exercise-induced angina: no
- ST depression induced by exercise (relative to rest): 2.3 mm
- Slope of peak exercise ST segment: downsloping
- Major vessels colored by fluoroscopy: 0
- Thallium stress test result: fixed_defect

Booleans are rendered as yes/no rather than True/False, and a missing ca or thal is written out as "not available" rather than dropped silently — so the model is told a field is absent instead of being left to infer it.

The prompt

A thin wrapper over the shared agent_common.build_generic_findings_prompt, with agent_role="a structured patient data analysis agent" and modality_label="structured patient data". No image_labels — this agent is text-only. The scaffold carries the same contract every modality agent signs: one of several parallel agents, no diagnosis, no conclusion depending on anything outside its own modality, one exact JSON shape, and evidence_ref restricted to the 13 keys.

A quirk worth naming

patient_info exists on every function in this module for interface symmetry with ECG and MRI, but no current caller of the library path uses it. Age and sex are this agent's own findings, complete with rationale and evidence_ref — unlike ECG and MRI, where demographics are external background context that has to be injected. The parameter is kept, not exercised.

The call, the parse, the retry

raw_response = llm_call(prompt)                                  # text-only, no images
findings, flags = parse_findings_response(raw_response, set(feature_dict.keys()))
merged_flags    = sorted(set(flags) | set(decision.deterministic_flags))

Default backend is generate_report_medgemma — Ollama, medgemma:4b, free and local, no API key. Because this modality is text-only, the UI can also offer the free Groq cloud backend here, which the MRI page cannot (it is text-only and could not see an image). A parse failure appends the error to the prompt and retries, up to max_retries + 1 attempts; the UI passes 2.

Validated end to end

A real MedGemma call on patient cleveland_0: 13 findings from 13 fields, every evidence_ref valid with no fabricated citation, first-attempt parse success, and 3 flags correctly raised and merged — abnormal_thallium_result_suspected, high_resting_bp_suspected, significant_st_depression_suspected.

That patient's actual ground truth is num = 0, no disease. Given flag precisions in the 0.53–0.77 range, this is a genuine expected false positive, not a bug — and worth recording as such rather than quietly picking a cleaner example.

The form — views/2_Patient_data.py

The UI entry point is a 13-field form rather than a file uploader, because the modality's input is tabular. Every field defaults to unknown: fill in only what you have, and anything left blank becomes None, with the related flag skipped rather than guessed. If every field is left unknown, no contribution is saved to the case at all.

Two encodings, one label

UCI encodes sex as 1 = male, 0 = female — the exact opposite of PTB-XL, where 1 = female. Rather than special-casing per page, each page normalises to the canonical label ("male"/"female") and hands that to build_patient_context_line, which accepts the label form directly. Both datasets' raw encodings converge on the same string, so the conflict cannot surface.

How to read these numbers

Precision here means: of the patients this flag fired on, what fraction actually have heart disease. Because prevalence is 0.459, a precision of 0.46 would be worthless — you would do as well flagging patients at random. That framing is what makes this modality's table interpretable in a way the ECG one is not.

  • The two strongest flags are the two most directly ischaemic. A positive thallium perfusion scan (F1 0.737) and any fluoroscopy-coloured vessel (F1 0.702) are both close measurements of the disease itself, so they track the outcome well. That is a sanity check on the pipeline, not a surprise.
  • Exercise-induced angina is the most precise flag (0.768) and one of the least sensitive (recall 0.547). It is a symptom, and plenty of disease is silent.
  • Resting blood pressure is the weakest by a wide margin (F1 0.380), driven entirely by recall — it is a risk factor, not a finding.

The per-record CSV was added specifically so the UI's Validation page could recompute this table live for the patient modality, exactly as it already did for ECG and MRI — the page had revealed that only this modality lacked the file.

08Down-
stream

Where the contribution goes

Sep Agent

The patient contribution joins ECG and MRI in generate_sep_agent_decision. Its flags carry retrieval phrasings in _FLAG_QUERY_PHRASES so the RAG layer receives a clinical query rather than a mangled identifier — multiple_vessels_involved_suspected becomes "coronary artery disease, multi-vessel involvement", significant_st_depression_suspected becomes "ST segment depression, exercise-induced ischaemia".

With use_kg=True, convergent_diagnoses reports a diagnosis supported by findings from at least two different modality agents. Coronary artery disease is the clearest example in the whole project: the ECG side reaches it through the MI superclass — via the deterministic inferior-Q flag, the learned signal embedding, or the ECG-image classifier — while the patient agent reaches it through four CAD/ischaemia flags. Hypertensive heart disease can converge across all three modalities at once. The convergence is computed deterministically by the graph and stored in decision.trace["kg_convergent_diagnoses"], so the small local model only narrates a pre-computed fact.

Case report

09Limit-
ations

Standing limitations

LimitationWhat it costs
303 patients, one hospital, one era. Cleveland is small and old. Every threshold on this page is calibrated to this sample. The two recalibrations are defensible because they moved toward better-validated physiology (Tanaka) or a clear F1 plateau, not because 303 patients settle anything.
Two flags are weak and stay weak. Resting BP (F1 0.380) and cholesterol (F1 0.550) barely clear the base rate at any threshold. They are kept for clinical meaning, and the weakness is published rather than hidden.
Several fields presuppose tests a patient may not have had. thal, ca, oldpeak, slope and thalach all come from an exercise test or fluoroscopy. On a partially filled form the strongest flags are exactly the ones that go silent — and the agent correctly skips them rather than guessing.
No severity, only presence. The 0–4 num scale is collapsed to a binary. Nothing here distinguishes mild from severe disease.
The flags are correlated, and the union treats them as independent. Four flags all indicating coronary artery disease is not four independent pieces of evidence. The knowledge graph makes the convergence explicit, but nothing weights or discounts it.
No text reference report exists for this modality. Only ECG has cardiologist reference reports, so there is no BLEU / ROUGE / cosine table here. This modality's accuracy claim is its flag validation — which is arguably the more honest measurement anyway.
patient_info is carried but unused. Kept for interface symmetry with ECG and MRI. Harmless, but it is dead surface area on four functions.
