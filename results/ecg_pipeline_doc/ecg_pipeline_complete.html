Cardiac multi-agent pipeline · ECG modality

The complete ECG pipeline

Two input paths — a raw signal and an image of a 12-lead ECG — each producing the same structured AgentContribution, dispatched by a single router and aggregated by the Sep Agent. Every learned/deterministic stage below is validated; the numbers are held-out results.

Single entry point

ecg_router.route_ecg_upload — one call, dispatched by file type, always returns a contribution.

The ECG modality accepts two kinds of input. A signal — a raw WFDB record or a CSV of samples — is the form used in research datasets such as PTB-XL. An image — a photo, a scan, or a printout of a 12-lead tracing — is the form a clinician actually holds in practice, and is therefore the more realistic deployment input. Rather than forcing one into the other, the system keeps two native pipelines and selects between them from the upload itself.

The router is the single entry point. It detects the branch from the file extension, runs the matching pipeline, and returns the same AgentContribution object either way, so every downstream consumer — the Sep Agent, the case report, the UI — is agnostic to which branch produced it. The router also guarantees a response: any failure it can anticipate is caught and turned into an explanatory contribution rather than an exception.

Path A

Signal pipeline

Raw WFDB / CSV → DSP → numeric features → deterministic flags → LLM findings.

The signal path is a two-stage design: classical signal processing turns the raw waveform into trustworthy numbers, then a language model narrates those numbers — it never invents them. The preprocessing pipeline runs, in order, baseline-wander removal, a powerline notch, wavelet denoising and z-score normalization, then Pan-Tompkins R-peak detection, from which the rate, RR intervals, QRS durations and rhythm-variability are derived. This core pipeline is single-lead by design.

Two additive modules read the full 12-lead signal alongside it, measuring amplitudes on the raw millivolt trace: the Sokolow-Lyon voltage index for left-ventricular hypertrophy and a territorial analysis of pathological Q waves for old infarction. A learned 1-D CNN embedding adds diagnostic-superclass probabilities that hand-crafted timing features cannot capture (P/T-wave and ST morphology). Every number then feeds two consumers: a set of fixed-threshold, deterministic flags — raised reliably regardless of the model — and a structured-findings prompt sent to MedGemma, whose JSON output is validated so each finding must cite a real computed feature.

Each flag was calibrated against PTB-XL ground truth, not set by intuition (the tachycardia threshold was moved 100→120 bpm, for instance). The recurrent alternative was studied too: a GRU handles variable-length input, but on these metrics — and on duration-robustness after length augmentation — the CNN stayed the production model.

Path A · detail

The signal branch, step by step

Classical DSP turns the waveform into trustworthy numbers; the LLM only narrates them.

Step 0 — Ingestion & guardrails (ecg_ingest, uploads only)

Any upload — a WFDB .hea/.dat pair or a CSV of samples — is normalized to the canonical form the pipeline expects: (n_samples, 12) in mV, explicit fs, PTB-XL lead order. validate() returns hard errors (block: bad fs, too short, all-NaN), warnings, and an enabled map that actually disables invalid feature families — e.g. fewer than 12 leads or an unconfirmed order turns the embedding and the voltage criteria off rather than producing a wrong number. Dataset records skip this (read directly via wfdb).

Step 1 — DSP preprocessing (ecg_preprocessing_pipeline, single lead)

#StageMethod
1Baseline-wander removalButterworth high-pass, 0.5 Hz (removes slow drift)
2Powerline removalIIR notch at 50 / 60 Hz
3Denoisingdb6 wavelet, 5 levels, universal soft-threshold (MAD σ)
4Normalizationz-score
5R-peaks → RRPan-Tompkins (band-pass → derivative → square → integrate → adaptive threshold)
6QRS durationper-beat amplitude-threshold heuristic (not a validated delineator)
7Rhythmcoefficient of variation of RR (irregular if CV > 0.15)

The core pipeline is single-lead by design (every stage runs on one 1-D array), and stage 6 is a heuristic — a validated QRS delineator (which would unblock bundle-branch block) is future work.

Step 2 — Numeric features (compute_feature_dict)

The single source of truth for the valid evidence_ref keys — the LLM may only cite a feature that exists here. It holds the rate / rhythm / QRS statistics, and — when the raw 12-lead signal is threaded in — two additive multi-lead families measured on the raw mV trace (Sokolow-Lyon LVH voltage, territorial pathological-Q), plus the learned embedding CNN's five diagnostic-superclass probabilities. The CNN is the retained model over a GRU, and length-augmentation makes it robust to variable duration (10 / 5 / 2 s).

Step 3 — Deterministic flags (detect_flags)

Fixed-threshold rules, each calibrated against PTB-XL ground truth (scp_codes), not intuition — the tachycardia cut, for instance, was moved 100 → 120 bpm by a validation sweep.

FlagRule
tachycardia / bradycardiaHR > 120 / < 60 bpm
wide_qrsQRS > 120 ms
irregular_rhythmRR CV > 0.15
lvh_sokolow_lyonS(V1)+max(R(V5),R(V6)) ≥ 3.5 mV
pathological_q_inferiorpathological Q in ≥ 2 inferior leads
embedding_<CLASS>_patternCNN probability > 0.5

If fewer than 2 QRS complexes are found, the LLM step is skipped entirely (skip_llm_call) — nothing to narrate.

Step 4 — LLM findings & assembly

build_findings_prompt → MedGemma → parse / validate (each finding must cite a real feature key) → the deterministic and LLM-proposed flags are merged into one AgentContribution(agent_id = "ecg"). Every finding is grounded in a computed number.

Why the signal branch needs no classifier or digitization. Unlike the image branch, here every value is native and measured (heart rate in bpm, QRS in ms, Sokolow-Lyon in mV), each compared to a validated threshold — so a finding is grounded and falsifiable by construction. The image branch had to recover those numbers (classifier probabilities, digitized rate/rhythm) precisely because pixels don't hand them to you.
Path B

Image pipeline

ECG photo / scan → adaptive preprocessing → image classifier + VLM reading.

The image path faces a problem the signal path does not: from pixels the clinical values are not handed to you — they must be recovered. Preprocessing itself only improves readability: each correction (sharpening, contrast equalization, gamma, deskew, resize) is applied in proportion to the measured severity of the defect, and a quality report travels with the image so the reader can weight its own confidence.

The clinical content then comes from three complementary components, each honest about what it is. A vision-language model reads the image and returns qualitative findings, labelled image-grounded. A discriminative image classifier (ResNet-18 trained on GenECG — PTB-XL rendered as images) gives real per-class probabilities and flags — because a VLM's self-reported confidence is not calibrated. And a lightweight digitization brick recovers the rhythm strip back into a lead-II signal, yielding the branch's only measured numbers (heart rate, rhythm). This mirrors the signal branch, where the embedding CNN — not the LLM — is the source of probabilities.

A design choice underlies this: the image is read as a first-class input, not forced wholesale through the signal pipeline. The trade-off is accepted honestly. The branch's diagnostic accuracy is its classifier (held-out macro F1 0.64, and — crucially — it detects myocardial infarction where a VLM-only reading scores 0.00); the digitization adds measured rate/rhythm (heart-rate MAE ≈ 1 bpm on GenECG), correcting the earlier belief that no values were recoverable from the image; and the VLM contributes qualitative narrative. Among local models, qwen2.5vl:7b gives valid JSON with no hallucination, whereas the ECG-specialized 4-bit fine-tune was the least reliable. Full 12-lead digitization (QRS width, Sokolow-Lyon voltage) remains future work.

Path B · detail

The image branch, step by step

Every stage, what it measures, and what it can and cannot claim.

Step 0 — Adaptive preprocessing (adaptive_ecg_pipeline)

The principle is proportional correction: each defect is measured, and the fix is applied in proportion to its severity — a clean image passes almost untouched, a degraded one is corrected harder. It does not verify that the image is even an ECG (a documented limitation).

DefectMeasured byAdaptive correction
BlurLaplacian varianceunsharp mask, amount 1.5 (severe) / 0.7 (mild) / 0 (sharp)
Low contrastpixel std-devCLAHE, clipLimit scaled 1 → 4 with the deficit
Brightnessmean greygamma curve pulling the mean toward 128
Skewmin-area-rect anglerotate, only 0.5°–15° (no perspective warp)
Orientation / channels / sizeEXIF · mode · widthEXIF rotate · RGB flatten · cap 1800 px / floor 400 px

A quality report (before/after metrics, source_quality_level, residual issues) travels with the image — it feeds the deterministic quality flags and is summarized in the VLM prompt so the model can weight its own confidence.

Order matters. The deterministic components below (classifier, digitization, quality) run before the VLM, and their outputs are injected into the VLM prompt as context. The VLM is the last compute step, not the first — it consumes the measured numbers, it does not produce them.

Step 1 — Image classifier → probabilities (learned, deterministic)

A ResNet-18: the image (384×384) → convolutional feature extraction → global pooling → a linear head with 5 outputs → a sigmoid per output → 5 independent probabilities (multi-label) over the PTB-XL superclasses CD · HYP · MI · STTC · NORM (NORM = normal). It is a discriminative model trained on GenECG images vs their true labels, so the probabilities are learned (a real image→class boundary), not a self-reported number like the VLM's confidence. Held-out validation: macro F1 0.64, MI 0.62 (vs a VLM-only 0.31 / MI 0.00).

Step 2 — Digitization → measured values (deterministic)

On the bottom rhythm strip (lead II), the image is turned back into a signal in four moves: ① the grid scale — isolate the reddish grid pixels, project them per column, and take the autocorrelation's first peak = pixels-per-mm (5 on GenECG); ② the trace — the darkest ink pixel per column (grid excluded), then despiked (Fix A: reject jumps from a local median + median filter); ③ calibration — the universal paper standard, 25 mm/s and 10 mm/mV, giving a signal in mV/s; ④ R-peaks — a combiner (Pan-Tompkins, falling back to a MAD-threshold detector, Fix B) whose timings give HR = 60 / median(RR) and CV = std(RR)/mean(RR) (rhythm regularity).

One lead suffices for rate/rhythm because the beat timing is shared across all 12 leads — you only need one to see when the heart beats. It does not give the superclasses (those are morphology/voltage, needing several leads). Held-out: heart-rate MAE ≈ 1 bpm, waveform correlation 0.77. Full 12-lead digitization (QRS width, Sokolow-Lyon voltage) is future work.

Step 3 — VLM → qualitative reading (qwen2.5vl:7b)

The VLM reads the image plus the injected context (quality summary + classifier probabilities + digitized measurements) and returns structured JSON findings. Its value field carries qualitative descriptors ("present", "narrow", "low"), grounded per lead (ecg_image_V2…) — never a measured number. (The value field is generic because the same schema serves the signal/MRI/patient agents, which do restate real numbers; when the VLM types a number it is an eyeballed guess, so we do not rely on it.) Among local models qwen2.5vl:7b gives valid JSON with no hallucination; the ECG-specialized 4-bit fine-tune was the least reliable.

Step 4 — Assembly, flags, and what the numbers mean

The output is one AgentContribution(agent_id = "ecg_image"): VLM findings + the union of deterministic flags + a trace holding the classifier probabilities and digitized measurements. Deterministic flags come from three threshold rules (no LLM, always reproducible): image quality (image_quality_*), classifier (pathology_<CLASS>_pattern_suspected when a probability > 0.5), and digitization (tachycardia / bradycardia / irregular_rhythm from HR > 120 / < 60 / CV > 0.15 — the same names as the signal branch).

A flag is a screening alert, not a diagnosis. The 0.5 threshold is the point of maximum uncertainty, not proof — a flag literally says "suspected". Read the actual probability for confidence (0.51 ≠ 0.95), and remember the model is F1 0.64. Real certainty comes from agreement across sources (classifier + VLM + digitization, and cross-modality KG convergence) and from human review. The system is decision support — a clinician makes the final call; it is deliberately not an autonomous diagnostician.

Aggregation & evaluation

Both contributions feed the same downstream, and both branches are evaluated.

Whichever branch ran, its contribution is combined by the Sep Agent into an integrated impression with full traceability, optionally enriched by retrieval over curated guidelines and by a clinical knowledge graph. Through the graph, an image-only case converges with the other modalities exactly as a signal case does — for example the image classifier's MI probability meets the patient agent's coronary-risk flags on coronary artery disease. The result is rendered as a case-report PDF.

Both branches are evaluated on the same twenty held-out records, against the same cardiologist reference report, so their generated narratives are directly comparable (BLEU, ROUGE and a biomedical clinical-cosine similarity). One caveat must be read carefully: the image branch scores higher on word-overlap metrics partly because its VLM prose reads more like a report, which is not the same as being more clinically correct — the branch's accuracy is its classifier, not this text table.
